# SRM31 独立设备层与离线构建 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task in the current session. Steps use checkbox (`- [ ]`) syntax for tracking. 本文是执行计划，本轮只创建文档，未开始实施。

**Goal:** 从当前 meta-SD3-12 创建 meta-SRM31 和独立构建目录，保留原有风扇功能、不引入 YU08 改动，复制已有源码及编译缓存后构建 SRM31 固件。

**Architecture:** 公共 OpenBMC 层沿用当前仓库；新设备层和构建目录独立。downloads 与 sstate-cache 使用普通文件复制，不共享旧缓存目录、不建立指向旧缓存的链接、不使用硬链接。tmp 由 SRM31 构建自行生成，旧 workspace 不参与构建。

**Tech Stack:** OpenBMC、Yocto / BitBake（当前层声明支持 mickledore）、AST2600、Bash、Python 3、rsync、Git。

## 6. Task 4：独立复制缓存

**Files:** build/SRM31/downloads、sstate-cache；validation/cache-copy-*.log。

- [ ] 首先复制 SD3-12 当前实际使用的下载缓存，以及其编译缓存：

```bash
rsync -a --no-owner --no-group --exclude='*.lock' \
  build/SD3-10/downloads/ build/SRM31/downloads/
rsync -a --no-owner --no-group --exclude='*.lock' \
  build/SD3-12/sstate-cache/ build/SRM31/sstate-cache/
```

这是普通复制；不使用 `--link-dest`、`cp -al` 或指向旧缓存的软链接。两个复制操作顺序执行，降低磁盘争用。保留成功下载对应的 `.done` 文件，不复制运行锁。

- [ ] 在任何 BitBake 命令执行前，用同源 `rsync -acn --itemize-changes` 加相同排除规则复核复制内容，预期无待复制的内容差异。保存校验输出和复制前后体积。
- [ ] 检查新缓存软链接。内部相对链接可保留；绝对指向旧缓存的链接改为新目录内对应路径。外部依赖须复制成独立内容或在新缓存内重建，不能残留读取旧目录的依赖。
- [ ] 检查下载 Git 仓库中的 `objects/info/alternates`、`commondir` 及 gitdir 外部引用；如存在，独立补齐对象和仓库结构后再解除引用，不得先删除引用造成缺对象。用 `git fsck --full` 验证相关仓库。

## 10. 异常处理与恢复边界

| 问题 | 处理 |
|---|---|
| 新目录已存在 | 检查进度和内容后恢复，不自动覆盖或删除 |
| 缓存仍缺源码 | 报告 recipe、SRC_URI、SRCREV / 校验和、已检查的本地来源；保持离线设置 |
| 复制中断 | 原目录不变；核对目标后用同参数 rsync 续传并重新校验 |
| Git 缓存同名冲突 | 保留主副本，按所需 commit 本地导入，不叠加仓库内部文件 |
| 缓存命中低 | 正常构建并报告统计，不更改机器身份 |
| 需要回退新设备 | 只撤回新层和新构建配置；缓存、日志先保留，删除大型目录需明确确认 |
| 原风扇程序编译失败 | 对照原配方、工具链和构建日志定位，不切换到 YU08 版本替代 |
